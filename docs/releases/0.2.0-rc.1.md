# rfile 0.2.0-rc.1 — experimental release candidate

This candidate provides a Rust file-type detector with bundled file 5.48 rules.
The downloadable binary is the default-feature x86_64 Linux/glibc CLI, including
gzip/zlib inspection. It uses neither libmagic nor a native helper at runtime.
The paired source archive includes locked vendored dependencies for offline builds.

## Changes since 0.1.0

- Shared IO, memory, work, cancellation and deadline controls for bounded
  inspection, including positional CDF metadata and ELF/core-note enrichment.
- Immutable timezone and locale contexts, checked date/float formatting and a
  bounded regex capture engine with documented GNU compatibility boundaries.
- Source-only options for additional Rust codecs, Linux CLI confinement and the
  experimental C interface, including typed source diagnostics and CLI database
  actions with native-style partial-load behavior.
- Explicit fixture and sandbox coverage reporting, with failures for required
  coverage that did not execute.
- Verification runs retain their source identity, commands, logs and failure or
  interruption status; a failed run cannot leave an older success as its result.
- CLI and vendored-source packaging from a clean, immutable Git commit, with
  checksums, compiler/platform metadata, notices, a manual and a prefix installer.
- Installation refuses existing files; removal checks its receipt and preserves
  unrelated or changed files.
- Candidate artifact CI, release-mode workspace checks and bounded pinned-oracle
  workflows with retained evidence. Rust 1.87 remains the source-build minimum.

The source also includes the bounded fuzz queue. Queue smoke tests establish
infrastructure behavior only; they do not complete sustained security qualification.

## Installation and scope

Download the binary archive and `SHA256SUMS`, verify its checksum, then extract it.
Run `bin/rfile --help` directly, or follow `INSTALL.md` to install into an explicit
user-owned prefix. The executable has no Python dependency; the optional installer
requires Python 3.11 or later. `MANIFEST.json` records the required glibc symbol
version and exact features. The release manifest identifies the source commit and
hashes of both archives.

The source archive requires Rust 1.87 or later and a native linker. Its vendored
dependencies support `cargo build --release --locked --offline -p rfile --bin rfile`.
See the included installation instructions and notices before redistribution.

Additional codecs, Linux Landlock/seccomp confinement and the C interface remain
experimental source options and are omitted from the downloadable binary. The
C library has the distinct name `librfile_magic`; no system utility or library is
replaced. Other platforms are not certified by this release.

## Known limitations

This is not a fully compatible libmagic replacement or a completed security audit.
Native regex-history behavior, broader source warnings, DEBUG and some IO/default
discovery semantics retain documented boundaries. The pinned and corrected profiles
have deliberately different behavior in named cases. Consult
[implementation status](../06-implementation-status.md) and
[release scope](../release-scope.md) for the exact promises.

Sustained fuzzing, branch/resource evidence, final-candidate replay and independent
security review remain open. The full 25-target minimum requires 600 measured
CPU-hours; ordinary tests and smoke campaigns do not satisfy it. File detection
does not establish that a file is safe.
