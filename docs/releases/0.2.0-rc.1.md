# rfile 0.2.0-rc.1 — published experimental prerelease

This [published release](https://github.com/JLuethe/rfile/releases/tag/v0.2.0-rc.1)
provides a Rust file-type detector with bundled file 5.48 rules.
The downloadable binary is the default-feature x86_64 Linux/glibc CLI, including
gzip/zlib inspection. It uses neither libmagic nor a native helper at runtime.
The paired source archive includes locked vendored dependencies for offline builds.

## Changes since 0.1.0

- Shared IO, memory, work, cancellation and deadline controls for bounded
  inspection, including positional CDF metadata and ELF/core-note enrichment.
- Default detection works in minimal images without timezone files: an absent
  implicit system zone uses UTC. Explicit named zones (including EST5EDT) still
  require timezone data; unavailable zones fail setup even for MIME-only input.
- Immutable timezone and locale contexts, checked date/float formatting and a
  bounded regex capture engine with documented GNU compatibility boundaries.
- Source-only options for additional Rust codecs, Linux CLI confinement and the
  experimental C interface, including typed source diagnostics and CLI database
  actions with native-style partial-load behavior.
- Explicit fixture and sandbox coverage reporting, with failures for required
  coverage that did not execute.
- Verification runs retain their source identity, commands, logs and failure or
  interruption status; a failed run cannot leave an older success as its result.
- Date comparisons distinguish the pinned C oracle's known uninitialized Windows
  timestamp failure from deterministic Rust rejection, retaining both results.
- CLI and vendored-source packaging from a clean, immutable Git commit, with
  checksums, compiler/platform metadata, notices, a manual and a prefix installer.
- Installation refuses existing files; removal checks its receipt and preserves
  unrelated or changed files.
- Candidate artifact CI, release-mode workspace checks and bounded pinned-oracle
  workflows with retained evidence. Rust 1.87 remains the source-build minimum.
- Descriptor-first no-follow inspection closes a pathname-swap read race;
  default terminal output escapes attacker-controlled diagnostic controls; and
  the optional installer uses retained directory descriptors. See the
  [published advisories](https://github.com/JLuethe/rfile/security/advisories).

The source also includes the bounded fuzz queue. Queue smoke tests establish
infrastructure behavior only; they do not complete sustained security qualification.

## Installation and scope

Download the binary archive and `SHA256SUMS`, verify its checksum, then extract it.
Run `bin/rfile --help` directly, or follow `INSTALL.md` to install into an explicit
user-owned prefix. The executable has no Python dependency; the optional installer
requires Python 3.11 or later. `MANIFEST.json` records the required glibc symbol
version and exact features. The release manifest identifies the source commit and
hashes of both archives.

The source archive requires Rust 1.87 or later and a native linker. Its vendored
dependencies support `cargo build --release --locked --offline -p rfile --bin rfile`.
See the included installation instructions and notices before redistribution.

Additional codecs, Linux Landlock/seccomp confinement and the C interface remain
experimental source options and are omitted from the downloadable binary. The
C library has the distinct name `librfile_magic`; no system utility or library is
replaced. Other platforms are not certified by this release.

## Known limitations

Truncated inputs can have different human descriptions because rfile checks
absolute read bounds inside `use` blocks. The pinned oracle can instead match
zero-filled bytes when only its block-relative check passes; observed families
include gzip, ZIP with `-k`, PNG/APNG, PGP and zstd. The observed truncated
`--mime-type` sweep matched; that is not a general compatibility guarantee.
Plain UTF-8 selection requires a completed decoded non-ASCII character (F-04b),
while retaining incomplete-tail tolerance after a completed character. BOM
handling and the one-byte very-short-file result are unchanged.
Non-wildcard string16 empty comparisons (for example =\0 and <z) remain outside
the narrow wildcard exception.
Malformed CDF sector geometry may fail at an earlier stage with a different
message. String16 wildcard reads past EOF synthesize an empty string safely.

In normal/MIME modes, empty regular files use metadata-only identification before
the permission check, even with `-E`; `-s` and annotation-only `--apple`/`--extension`
disable that shortcut. Other unreadable regular files
produce a descriptive permission result in every mode, including `-E`; missing-file/stat and other genuine IO failures retain their
error behavior. FIFO content inspection (`-s`) returns an explicit unsupported
error without opening the FIFO; ordinary FIFO metadata identification remains.

On direct empty files, mixed `-i --apple` produces one MIME result instead of
the oracle's concatenation with an annotation result. On regular symlink targets,
including readable, empty and chained targets, it produces only the target
result (the permission description if unreadable), without the oracle's symlink
MIME prefix (F-08d). Earlier 8e33173 emitted only the symlink MIME result for
mixed flags. Annotation requests follow regular symlink targets;
non-regular targets receive a controlled unsupported error, with directory-target
wording differing from the oracle's `Is a directory` diagnostic.

Broken output pipes produce quiet status 1. A stdout descriptor already closed
before Rust startup is reopened as `/dev/null`, so that case can exit 0 silently.
The CLI's checks after runtime startup do not recover the original descriptor
state; this limitation remains a maintainer disposition item.

With `-z`/`-Z`, decoded output exceeding the default 7 MiB `bytes` cap is an
explicit error (status 1), rather than libmagic's prefix sampling. No inner or
outer description is returned for that failed inspection. This preserves the
complete-stream/integrity contract; a prefix cannot establish the unseen tail's
integrity. For a larger trusted workload use, for example,
`-P bytes=16777216 -z` (16 MiB); other budgets still apply. Omit `-z`/`-Z` to
identify the wrapper without decoding. This is a deliberate compatibility
boundary, not a claim that every large compressed file is corrupt.

An explicitly configured named timezone, such as `TZ=America/New_York`, requires
the corresponding timezone data. In a minimal image without it, all classification
modes fail during setup, including MIME-only and files without dates. Install
timezone data, unset `TZ`, or use `TZ=UTC` when UTC is intended. Unlike glibc,
an unresolved explicit zone does not silently fall back to UTC. Some short forms
such as `TZ=EST5EDT` also require timezone data; `TZ=UTC0` and complete POSIX
rules such as `TZ=PST8PDT,M3.2.0,M11.1.0` work without it.

This is not a fully compatible libmagic replacement or a completed security audit.
Native regex-history behavior, broader source warnings, DEBUG and some IO/default
discovery semantics retain documented boundaries. The pinned and corrected profiles
have deliberately different behavior in named cases. Consult
[implementation status](../06-implementation-status.md) and
[release scope](../release-scope.md) for the exact promises.

Sustained fuzzing, branch/resource evidence, final-candidate replay and independent
security review remain open. The full 25-target minimum requires 600 measured
CPU-hours; ordinary tests and smoke campaigns do not satisfy it. File detection
does not establish that a file is safe.
