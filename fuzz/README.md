# Fuzzing

Twenty-three buildable libFuzzer targets cover compiled databases, source, classification, combined rules/data, formatting, encodings, registry/decompression and ten per-codec targets, positional CDF containers, property sets and seekable ELF/core notes. Production detection remains independent of the fuzz engine and any C library.

```sh
cargo check --manifest-path fuzz/Cargo.toml --locked --bins
cargo install cargo-fuzz
cargo +nightly fuzz run classify -- -max_len=65536
cargo +nightly fuzz run compiled_database -- -max_len=1048576
cargo +nightly fuzz run magic_source -- -max_len=65536
cargo +nightly fuzz run rules_and_data -- -max_len=65536
cargo +nightly fuzz run formatter -- -max_len=73
cargo +nightly fuzz run encoding -- -max_len=65536
cargo +nightly fuzz run compression -- -max_len=65536
cargo +nightly fuzz run cdf_container -- -max_len=65536
cargo +nightly fuzz run cdf_properties -- -max_len=65536
cargo +nightly fuzz run elf_seekable -- -max_len=65536
```

Run from the repository root. Seed content targets with public upstream fixtures and the database target with small valid compiled custom rules. Keep minimized failures and record seed, toolchain, limits and feature manifest. No 24-hour fuzz campaign has been completed. Stable deterministic mutation smoke testing is separate:

```sh
cargo test --release --locked --test hardening -- --ignored --nocapture
```

CDF container seeds are generated by `python3 tools/cdf_fixtures.py` under `tests/fixtures/cdf`; copy these to the ignored `fuzz/corpus/cdf_container` directory. Property seeds must be actual section streams, not entire containers. `cdf::inspect` uses positional SliceView reads and shared budgets, so these targets exercise random-access paths without opening attacker-chosen filesystem paths. Smoke results are separate from sustained final-candidate release gates.

`tools/fuzz_campaign.py TARGET --seconds 30` records a smoke run with actual `wait4` CPU time, peak RSS, instrumented-binary/source hashes, initial/final corpus hashes and fuzzer statistics. It supervises wall-time overruns and preserves failures. A requested future final-candidate run uses `--seconds 3600 --cpu-hours 24`; elapsed wall hours do not substitute for measured CPU hours, and resume rejects a changed binary/source/configuration. Sustained campaigns and independent review remain explicit release gates after implementation through sandbox and C ABI. They are not completed by short smoke runs.

The fuzz dependency enables `extended-codecs` explicitly even when the default production build does not. Per-codec targets are `codec_gzip`, `codec_zlib`, `codec_bzip`, `codec_xz`, `codec_lzma`, `codec_lzip`, `codec_zstd`, `codec_lzfour`, `codec_compress` and `codec_zip`. They decode both profiles with shared input/output/window/memory/work/member ceilings and assert that owned reservations release. Their shared `codec_driver.inc` is included in campaign source identities. Seed from `tests/fixtures/compression` using its manifest; independent encoder programs are only needed when regenerating committed fixtures.

R5's ten ASan smoke runs executed 1,412,219 cases over 202.63 measured CPU seconds, with no reported failure. The per-target records retain exact candidate/tool/corpus hashes. This does not satisfy a 24-hour target gate or independent review.

`regex_captures` mixes fixed valid capture programs with arbitrary bounded byte
patterns and input; both semantic profiles execute with shared work, step,
state and memory caps. Seeds cover nested/empty/unset/repeated references and
quantifier cycles. Its sanitizer record is separate from mathematical/corpus
conformance and does not close native glibc history restrictions.

The R6a final capture smoke executed 3,002 cases over 27.43 measured CPU seconds
with no reported ASan failure. See `reports/fuzz-regex_captures.json` for the exact
source/binary/corpus identity. It is not 24-hour or independent-review evidence.

`display_locale` exercises C and C.UTF-8 filename/result conversions, widths,
invalid/incomplete sequences, bounded expansion and guard cleanup after cap
errors. The campaign identity now includes platform-crate source/manifests.
Its final smoke ran 689,299 cases over 30.99 measured CPU seconds, without a
reported failure; this does not instrument/prove glibc or satisfy sustained
security gates. The core's C display remains safe Rust.


`formatter` now separates type, description length and payload, exercising byte,
f32 and f64 conversions through both semantic profiles. `time_context` parses
bounded POSIX expressions or TZif bytes and evaluates local/Windows date rules
in both profiles, without opening input-selected paths or modifying TZ. Seed
with explicit J/n/M and perpetual-DST rules plus public TZif data. Neither target
is a claim that the sustained campaign has completed.
