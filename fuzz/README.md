# Fuzzing

Ten buildable libFuzzer targets cover compiled databases, source, classification, combined rules/data, formatting, encodings decompression, positional CDF containers, property sets and seekable ELF/core notes. Production detection remains independent of the fuzz engine and any C library.

```sh
cargo check --manifest-path fuzz/Cargo.toml --locked --bins
cargo install cargo-fuzz
cargo +nightly fuzz run classify -- -max_len=65536
cargo +nightly fuzz run compiled_database -- -max_len=1048576
cargo +nightly fuzz run magic_source -- -max_len=65536
cargo +nightly fuzz run rules_and_data -- -max_len=65536
cargo +nightly fuzz run formatter -- -max_len=63
cargo +nightly fuzz run encoding -- -max_len=65536
cargo +nightly fuzz run compression -- -max_len=65536
cargo +nightly fuzz run cdf_container -- -max_len=65536
cargo +nightly fuzz run cdf_properties -- -max_len=65536
cargo +nightly fuzz run elf_seekable -- -max_len=65536
```

Run from the repository root. Seed content targets with public upstream fixtures and the database target with small valid compiled custom rules. Keep minimized failures and record seed, toolchain, limits and feature manifest. No 24-hour fuzz campaign has been completed. Stable deterministic mutation smoke testing is separate:

```sh
cargo test --release --locked --test hardening -- --ignored --nocapture
```

CDF container seeds are generated by `python3 tools/cdf_fixtures.py` under `tests/fixtures/cdf`; copy these to the ignored `fuzz/corpus/cdf_container` directory. Property seeds must be actual section streams, not entire containers. `cdf::inspect` uses positional SliceView reads and shared budgets, so these targets exercise random-access paths without opening attacker-chosen filesystem paths. Smoke results are separate from sustained final-candidate release gates.

`tools/fuzz_campaign.py TARGET --seconds 30` records a smoke run with actual `wait4` CPU time, peak RSS, instrumented-binary/source hashes, initial/final corpus hashes and fuzzer statistics. It supervises wall-time overruns and preserves failures. A requested future final-candidate run uses `--seconds 3600 --cpu-hours 24`; elapsed wall hours do not substitute for measured CPU hours, and resume rejects a changed binary/source/configuration. The current user scope ends with implementation/verification through sandbox and C ABI; long campaigns and independent review remain subsequent release work.
